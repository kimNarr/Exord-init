# 2026-09-10 — v0.4 복구와 안전장치, CI

## 한 일
- **복구 명령**: 중간에 멈춘 실행을 살펴보고(inspect), 별도 승인을 받아 되돌리고(rollback), 남은 실행을 찾는(list) 기능. 복구가 필요한 실행이 있으면 새 계획을 막는다.
- 적용을 마치기 전에 계획에 선언된 검증(AGENTS.md 크기, manifest 형식, 필수 항목)을 실행하고, 하나라도 실패하면 안전하게 되돌리게 했다.
- 운영체제 잠금으로, 프로그램이 죽어도 프로젝트가 영원히 잠긴 채 남지 않게 했다.
- JSON 정규화 규칙(RFC 8785)을 맞춰 잘못된 문자 처리 오류를 고쳤다.
- **CI**: Linux(amd64·arm64), Windows, macOS에서 빌드·검사·테스트가 자동으로 돌게 했다.
- Windows·macOS CI에서만 실패하던 임시 폴더 경로 문제(짧은 이름, 심볼릭 링크)를 테스트 쪽에서 고쳤다.

## 결정과 이유
- **기본은 실패로 닫힌다(fail-closed)**: 모르는 검증이나 확인할 수 없는 상황이면 진행하지 않는다. 사용자의 프로젝트 파일을 망가뜨리는 것보다 멈추는 편이 낫다.
- **승인은 계획에 묶인다**: 사용자가 승인한 그 계획(해시)에만 적용할 수 있고, 계획이 바뀌면 다시 승인을 받아야 한다.

## 만든 것

- 복구 inspect·rollback·list, OS advisory lock, apply 검증과 당시 두 지점의 fault injection. 근거: `5058f47`.
- JSON 문자 이스케이프 회귀 테스트, 스키마·CLI 통합 테스트와 4개 환경의 GitHub Actions workflow.
- Windows 짧은 경로와 macOS 임시 경로를 정규화한 테스트 fixture. 근거: `49b72e8`의 변경과 커밋 설명.

## 배운 점

- 로컬에서는 통과하는데 다른 운영체제 CI에서만 실패하는 경우가 있었다. 안전 검사(링크를 따라가지 않기)는 맞게 동작한 것이고, 고칠 곳은 테스트였다.

> 2026-10-16에 커밋을 근거로 복원·보완했다. CI 설정과 당시 경로 오류의 수정 근거는 확인했으며, 현재 원격 CI 실행 결과는 이 기록 점검에서 확인하지 않았다.
